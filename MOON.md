# moon

Terminal chat client for language models, written in Rust. Cargo workspace:

- `crates/core` (`moon-core`): the `Provider` trait, `Registry`, configuration, XDG paths, JSONL sessions, file context (`context.rs`).
- `crates/providers/ollama` and `crates/providers/openai`: the two provider implementations (native Ollama API; OpenAI-compatible chat completions). Both send the request's `tools` and turn the model's tool calls into `ChatEvent::ToolCall`.
- `crates/agent` (`moon-agent`): the model editing files and running commands, behind `/tools`. Four folders, four ideas: `harness/` (the loop, a pure state machine fed with events and answering with commands), `agents/` (the `editor` and the `reader`: a prompt plus a `Policy`, the tools following from it), `tools/` (a closed enum: `read_file`, `list_dir`, `edit_file`, `write_file`, `run_command`; `catalog.rs` is the one catalogue of capabilities — the file tools and a fixed list of commands, each with a permission `off · ask · allow` — `run_command.rs` checks a call and runs it with no shell), `sandbox/` (the boundary: every path stays under the start-up directory, `.git/` and secrets are never touched, writes are atomic). Depends on `moon-core` only; `docs/harness.md` is the design, `docs/tools.md` the user's guide, with a table generated from `CATALOG` (`UPDATE_DOCS=1 cargo test -p moon-agent docs`).
- `crates/tui` (`moon-tui`): the ratatui interface. `app/mod.rs` holds the state (Elm-style `Action`/`update`) and each other module under `app/` is one `impl App` about one concern (keys, chat, slash commands, files, models, render, status; `agent.rs` runs the harness's commands and the approval panel); `view/` is the rendering (`panel.rs` for the bottom panel: lists, help, dialogs and the approval panel, all docked under the conversation instead of floating over it; `diff.rs` paints a diff); `sysmon/` samples CPU, RAM and GPU memory (`gpu.rs`: NVML on NVIDIA, sysfs on AMD) for the bottom-right row and `/machine`.
- `crates/updater` (`moon-updater`): the GitHub releases API, version order, checksum, archive and the in-place swap of the binary. No terminal and no provider: `moon-tui` puts the panel on top (`update/`) and the start-up check reads its daily cache.
- `crates/cli` (`moon-cli`): the `moon` binary.

Conventions: identifiers, comments, log messages and the Markdown docs (`README.md`, `CONTRIBUTING.md`) in English; every user-facing string in English. No source file over 1000 lines. Visual identity: the Moon design system (single brand color `#8fb8ff`, pixel crescent, square corners).
